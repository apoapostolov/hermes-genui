## Known gap this PR does not fix

**#75's Markdown serializer predates #35.** `web/src/lib/markdown.ts` treats `histogram` and `range` as plain line charts, and `markdown.corpus.json` was pinned before those kinds existed. Exporting a histogram or range board as Markdown therefore disagrees with the chat fallback (`hooks/text_fallback.py`), and `tests/hooks/test_export_markdown_corpus.py` fails.

That is a re-port of `blocks/chart.py::_bins_line` and `_windows_line` into `markdown.ts` plus a deliberate `GARZA_CORPUS_REGENERATE=1` run — leo's work on his own PR, not something to smuggle into an integration branch. **Deliberately left red.**

## Known interaction bug, not fixed here

The expand control (#72) and the board menu (#75) share `position: absolute; top: 6px; right: 6px; z-index: 1` on `.hb-tag`, so they sit on top of each other; each per-block download button is positioned by host-space arithmetic (`block.right - host.left - 34`) that can overlap a card's title, a table header sort control, or a legend, and can overflow a narrow board. The fix is to anchor the download button inside each widget's own corner instead of the tag-wide overlay layer. Scoped separately — flagged here because it only exists once #72 and #75 meet.
